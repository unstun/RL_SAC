# Horizon 参数消融实验 (V13 Ablation Study)

> 来源版本: V13 — Horizon 参数消融（Dueling+MHA 固定）
> 原始留档: `docs/versions/v13/RESULTS.md`

## 实验动机

V12 正式评测中 RL 路径长 4-10%、时间慢 14-17%。
肉眼观察到 RL 在障碍物附近过度避让（大转弯），根因是 `forest_adm_horizon=30`
（常值动作前瞻 1.5s）对于 0.05s 决策频率的反应式智能体过于保守。

## 实验设计

- **固定配置**: Dueling+MHA, profile=v9p2, episodes=150
- **变量**: `forest_adm_horizon` = 25 / 20 / 15 / 10
- **对照**: H30 (V12 正式评测 runs=20) + Hybrid A\*-MPC
- **推理**: runs=5, short/long (`--rand-two-suites`)
- **纯 CLI override**, 无代码改动

## 关键发现

### 1. 非单调行为

Horizon 缩短并非单调改善：H25/H20 比 H30 全面恶化，H15 反而最优。
推测原因：H25/H20 处于"不上不下"区间——掩码既不够严格保证安全，
也不够宽松让 Q 网络自由学习。

### 2. H15 的矛盾

- short SR=1.0 且 inad_rate=10.7%（最佳），但 long SR 仅 0.4
- Long 场景需要更多步决策，宽松掩码增加累积错误概率

### 3. H10 的启示（最重要）

- 成功时路径最短: **15.40m < A\*-MPC 16.87m**
- 成功时时间最快: **9.57s < A\*-MPC 10.0s**
- **证明了掩码确实是路径过长的根因**
- 但 SR 过低 (0.6/0.2)，训练量不足以学会无掩码保护下的安全行为

## 结论

1. Horizon 参数调优**无法同时兼顾 SR 和路径长度**
2. H30 仍为综合最优配置（SR=0.95/0.95）
3. H10 证明了方向正确：若能提高短 horizon 下的 SR，路径可超越 A\*-MPC
4. 下一步需结构性改进（动态 horizon / 连续动作空间 / 更多训练量）
